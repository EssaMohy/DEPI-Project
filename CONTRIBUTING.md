# Contributing

Thanks for your interest in contributing to DEPI! This document explains the basic workflow and expectations for contributions.

Process

- Fork the relevant repository (or create a branch if you have push access).
- Create a feature branch with a descriptive name: `feature/short-description` or `fix/short-description`.
- Write clear, focused commits. Squash or tidy commits before opening a PR if appropriate.
- Open a Pull Request against the `main` branch of the target repo. Include a description of what you changed and why.

Code standards

- Follow the style in the repository. Use the provided lint and format tools (`npm run lint`, `npm run format`).
- Add tests for new features or bug fixes when applicable.

PR Checklist

- [ ] Code builds and tests pass locally
- [ ] Linting and formatting are applied
- [ ] Relevant documentation updated (README, API docs)
- [ ] Descriptive PR title and description

Review and merging

- At least one approval is required for merging. Some paths may require additional approvals as defined in `CODEOWNERS`.
- Use `squash and merge` for small fixes and `merge` for larger feature work per reviewer guidance.

Thank you for contributing — we appreciate your help!
